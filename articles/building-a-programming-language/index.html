図解キャプション　言語処理系は、入力文字列を段階的に構造化し、評価またはコード生成へ渡す。[1][2][3][4]

概要

自作言語は、最初から実用言語を目指すのではなく、仕様を小さく固定し、字句解析、構文解析、抽象構文木（AST）、評価器の順に作ると理解しやすい。本稿では、四則演算だけを扱う極小言語「MiniCalc」を例に、動くインタプリタを組み立てる。後半では、コンパイラ、仮想マシン、LLVMへの拡張経路と限界を示す。

この記事の見取り図

  1. 言語を「文法」と「意味」と「実行」に分ける。
  2. 数値と演算子をトークン化する。
  3. 優先順位を保つ構文解析でASTを作る。
  4. ASTを再帰的に評価する。
  5. テスト、エラー、型、実行方式を段階的に追加する。

定義と全体像

プログラミング言語は、文字列の書き方（構文）だけでなく、その構文が何を意味するか（意味論）と、意味を実行へ変換する仕組み（処理系）からなる。典型的な処理の流れは、ソースコード → トークン列 → AST → 評価または中間表現 → 実行である。[1][2][3][4]

「自作」の最初の目標は、言語仕様を一枚に書ける規模にすることだ。MiniCalcの仕様は、数値、+ - * /、括弧、空白だけとする。*と/を+と-より先に評価し、入力 2 + 3 * 4 の結果を14と定める。

歴史的背景・古典的理解

1957年のFORTRAN論文は、数式に近い表記を機械語へ変換する自動コーディングシステムを記述した歴史的一次資料である。[5] 1962年のLISP 1.5 Programmer's Manualは、記号式、関数、リスト構造を中心とする別の言語設計と処理系利用の文脈を示す。[6] ここから分かるのは、言語設計には単一の正解がなく、数値計算、記号処理、教育、組込みなど目的が構文と実行方式を方向づけるという点である。これらの歴史資料を、そのまま現在の実装標準とみなしてはいけない。

現在の標準的理解

現代の教材では、字句解析と構文解析を分離し、ASTを後段の評価・コード生成で利用する構成が基本的な学習経路として説明される。[1][2][4] LLVM公式チュートリアルは、Kaleidoscopeを字句解析、再帰下降・演算子優先の構文解析、AST、LLVM IR生成、JITへ段階的に拡張する。[1][2][3] ただし、実際の処理系は型検査、名前解決、最適化、診断、標準ライブラリ、デバッグ情報、パッケージングなどを追加で必要とする。

詳細説明

1. 字句解析

2 + 3 * 4
NUMBER(2), PLUS, NUMBER(3), STAR, NUMBER(4), EOF

字句解析器は左から文字を読み、数値や記号をトークンへ変換する。未知の文字は位置付きエラーにする。実装の要点は、数値の終端、空白の扱い、入力末尾、エラー位置をテストすることである。

2. ASTと構文解析

ASTは括弧や空白をそのまま保存するのではなく、計算の構造を表す。入力 2 + 3 * 4 は、+を根にし、左に2、右に*（子は3と4）を持つ木になる。[2]

Expr := Term (("+" | "-") Term)*
Term := Unary (("*" | "/") Unary)*
Unary := ("+" | "-") Unary | Primary
Primary := NUMBER | "(" Expr ")"

この文法を再帰下降で実装すると、ExprがTermを呼ぶため、乗除が加減より深い木になる。構文エラーには、期待したトークン、実際のトークン、位置を含める。[2]

3. 自作例：MiniCalcの評価器

以下はPythonで書いた最小の実行部分である。字句解析器とパーサがASTを返すと仮定する。

from dataclasses import dataclass

@dataclass
class Number:
    value: float

@dataclass
class Binary:
    left: object
    op: str
    right: object

def evaluate(node):
    if isinstance(node, Number):
        return node.value
    left, right = evaluate(node.left), evaluate(node.right)
    if node.op == "+": return left + right
    if node.op == "-": return left - right
    if node.op == "*": return left * right
    if node.op == "/": return left / right
    raise ValueError(f"unknown operator: {node.op}")

tree = Binary(Number(2), "+", Binary(Number(3), "*", Number(4)))
assert evaluate(tree) == 14

この例の価値は短さにある。まず木を直接作って評価器を検証し、次に字句解析器とパーサを接続する。1 / 0、閉じ括弧の欠落、未知の文字、空入力を失敗例として固定すると、仕様と実装のずれを発見しやすい。

4. 評価からコンパイルへ

インタプリタはASTを直接評価できる。一方、コンパイラはASTから別の命令列や中間表現を生成し、後段で実行する。LLVMを使う場合、ASTからLLVM IRを生成する道筋が公式チュートリアルで示されているが、LLVMの版とチュートリアルの対応を確認する必要がある。[3] 実用上は、まずインタプリタで意味を確定し、その後にバイトコードやネイティブコードへ進むとデバッグ対象を分離しやすい。

応用・実践上の含意

  • 目的を「学習」「設定ファイル」「DSL」「高速実行」のいずれかに絞る。目的が異なれば、型、エラー、実行方式の優先順位も変わる。
  • 文法を書いてから実装し、正常系と異常系を同じテスト表に置く。
  • 最初は数値だけ、次に変数、関数、条件分岐の順で拡張する。各段階で言語リファレンスとサンプルを更新する。
  • 教材のコードは設計上の簡略化を含む。LLVM自身もKaleidoscopeを教育用に単純化した例として位置づけている。[1]

限界・論争点・未解決事項

「最適な」構文解析法や実行方式はない。再帰下降、演算子優先法、パーサジェネレータなどは文法、エラー回復、保守性の要求で選ぶ。[2][4] 動的型付けと静的型付け、ガベージコレクションと手動管理、インタプリタとコンパイラにもトレードオフがある。小さな例から性能、安全性、互換性を外挿することはできない。また、診断品質、Unicode、浮動小数点、整数オーバーフロー、並行性、標準ライブラリまで含めると、言語処理系は急速に大きくなる。したがって、本稿のMiniCalcは「実用言語の完成品」ではなく、処理系の境界を学ぶ再現可能な足場である。

まとめ

自作言語の第一歩は、壮大な機能表ではなく、短い仕様と一つの実行例である。MiniCalcでは、トークン、AST、評価器を分離することで、2 + 3 * 4を14へ変換する経路を検証できる。そこからテスト、診断、変数、型、バイトコード、LLVM IRへ一段ずつ進める。[1][2][3][4]
